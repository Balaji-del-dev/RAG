1What is query transformation?

Interview answer — say this first
In simple words

Before searching, we fix the user's question so the search can find the right documents. For example, we turn "and does it include support?" into "Does the Enterprise plan include support?", or split one complex question into two simpler ones.

2Why do we need it?

Search can only find what the query describes. Real user questions are often short, vague, misspelled, full of words like "it" and "that", or several questions in one. A little preparation fixes many "it didn't find anything" failures.

Raw question sent to search

  • "And does it include support?" → generic results
  • "PTO rules?" → misses "paid time off"
  • "Compare India and Germany leave" → only one country found

Transformed question

  • "Does the Enterprise plan include support?"
  • "paid time off (PTO) rules"
  • Two searches: India leave policy + Germany leave policy
Analogy: a good librarian asks back

When you ask a librarian "what about the second one?", they remember your earlier question. When you ask something vague, they turn it into precise search terms. Query transformation gives the search system this skill before it searches.

3How does it work?

Cheap steps run on every question. Expensive LLM-based steps are added only when evaluation shows they help.

1

Normalize

Clean the text: extra spaces, odd characters, length limits. Detect the language.

2

Classify the intent

Decide what kind of request it is: a document question, an ID lookup, small talk, or out of scope. Route or refuse early.

3

Condense follow-ups

In a chat, turn the latest message into a standalone question using the chat history.

Example: "And does it include support?" → "Does the Enterprise plan include support?"
4

Extract and validate filters

Pull out filters like product, year or department, and check them against the allowed values.

Example: {product: "Enterprise"}
5

Optional: advanced rewriting

Only when needed: rewrite, generate several versions (multi-query), write a hypothetical answer (HyDE), or split the question (decomposition).

4Example: step by step

A follow-up question in a chat
  1. History: "What is the price of the Enterprise plan?" — already answered.
  2. New message: "And does it include support?"
  3. Condense with history → "Does the Enterprise plan include support?"
  4. Extract filters → {product: "Enterprise"}, checked against the allowed products.
  5. Search with the standalone question. Without step 3, searching "does it include support" returns generic results.
A comparison question: "Compare the leave policies of India and Germany"

One search for this mixed question returns chunks from only one country. Decomposition creates two questions — "leave policy India" and "leave policy Germany" — searches for each, and the LLM writes a comparison with citations from both.

5Important terms

Query normalization

Cleaning the question: spaces, characters, length limits.

Intent classification

Deciding what kind of request it is: document question, ID lookup, small talk, out of scope.

Condense question

Turning a follow-up into a standalone question using the chat history.

Query expansion

Adding synonyms or related words to the query.

Multi-query

Searching with several versions of the same question and merging the results.

HyDE

Hypothetical Document Embeddings: search using a generated answer instead of the question.

Decomposition

Splitting a complex question into simpler sub-questions.

Query routing

Choosing which data source, index or tool should answer.

Remember

Every extra LLM call adds time and can change the meaning. Start with a baseline, and add a technique only when evaluation shows it fixes real failures.

7Advantages and limitations

Advantages

  • Follow-up questions work in chat
  • Finds documents that use different words
  • Handles multi-part and comparison questions
  • Routes requests to the right source

Limitations

  • Extra LLM calls add latency and cost
  • A rewrite can change the user's meaning
  • Filters guessed by an LLM must be validated
  • More steps are harder to debug

9How to explain it in an interview

Your 1-minute answer

DefinitionQuery transformation is the set of techniques that prepare or reformulate a user's question before retrieval, so that the search finds the right documents.

HowSimple steps run on every query: normalization, intent classification and condensing follow-up questions using the chat history. Advanced techniques use an LLM: query rewriting, multi-query retrieval, HyDE and decomposition.

ExampleIn a chat, "And does it include support?" is condensed into "Does the Enterprise plan include support?" before searching; otherwise the search returns generic results.

Trade-offEach model call adds latency and can change the meaning, so I add advanced techniques only when evaluation shows they fix real failures, and I validate any extracted filters.

Don't say"We use HyDE and multi-query on every request to improve recall."
Say instead"Start with a baseline; add a technique only when evaluation shows it fixes real failures."
Don't say"We send the user's latest message straight to search."
Say instead"In conversations, we first condense follow-ups into standalone questions."
