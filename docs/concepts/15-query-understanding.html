1What you will learn

  • Cheap, deterministic query preparation: normalization, language detection and filter extraction.
  • Query classification and routing.
  • Rewriting follow-up questions into standalone questions.
  • Multi-query, HyDE, decomposition and step-back prompting, and their costs.

2Why it matters

Real questions are short, vague, misspelled, full of pronouns ("what about the second one?"), or several questions in one. Retrieval can only find what the query describes. A little preparation fixes many "the system didn't find it" failures — but every LLM call added here costs latency and can change the meaning of the question.

3Core ideas

Step 1 — Prepare (always, cheap)

  • Normalize: trim, Unicode-normalize, collapse whitespace, enforce length limits.
  • Detect language: pick analyzers, and possibly answer in the user's language.
  • Extract filters: "HR policies from 2026" → {department: "HR", year: 2026}, either rule-based or with a small model, then validated against allowed values.

Step 2 — Classify and route

Step 3 — Conversation: condense to a standalone question

History: "What is the Enterprise plan's price?"+ Follow-up: "And does it include support?"→ Standalone: "Does the Enterprise plan include support?"

Without this step, the retriever searches for "does it include support" and finds nothing specific.

4Advanced transformations

Query rewriting / expansion

Rewrite into clearer search terms, and add synonyms or expanded acronyms ("PTO" → "paid time off").

Multi-query

Generate 3–5 paraphrases, retrieve for each, then fuse the results (lesson 16). Higher recall, 3–5× retrieval cost.

HyDE

Ask the LLM for a hypothetical answer, embed that, and search. It matches passage style better than a short question. Risk: the made-up answer can pull in wrong topics.

Decomposition

Split "Compare the leave policies of India and Germany" into one question per country, retrieve each, then combine.

Step-back prompting

Also search a more general question ("How does carry-over work in general?") to fetch background context.

Routing

Pick the right index, collection or tool (documents vs a SQL table of metrics) based on the question.

Earn every LLM callEach transformation adds 0.3–2 seconds and new failure modes. Add one only when the evaluation set shows it fixes real failures — the platform rule is "baseline first".

5In the real world

  • Keep the original query as well: use both, or fall back to it when a rewrite drifts.
  • Log every transformation and show it in traces. "Why did it search for X?" is a common debugging question.
  • Small local models are usually enough for classification and condensing. The main LLM is not needed.
  • Validate extracted filters against allowed values. Never pass model output straight into a query.

6Common mistakes

  • Searching with the raw follow-up question in multi-turn chat.
  • Stacking HyDE + multi-query + decomposition on every query "to be safe".
  • Letting an LLM invent filter values that don't exist, so zero results come back.

8Check yourself

Why must follow-up questions be condensed before retrieval?
They depend on earlier turns ("it", "the second one"). Searching them alone retrieves irrelevant or generic chunks.
What is HyDE, and what is its main risk?
Embedding a hypothetical answer instead of the question. If the guessed answer is wrong or off-topic, it steers retrieval to the wrong passages.
Why validate filters extracted by a model?
The model may produce values that don't exist or are out of scope, causing empty results — or, worse, bypassing intended restrictions.
