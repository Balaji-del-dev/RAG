1What you will learn

  • Tool (function) calling: how an LLM asks your code to do something.
  • Agentic RAG: the model decides when and what to retrieve, in a loop (ReAct).
  • Corrective RAG, Self-RAG, multi-hop retrieval, GraphRAG and text-to-SQL.
  • The Model Context Protocol (MCP), and when all of this is worth the cost.

2Why it matters

A fixed pipeline (retrieve once, answer once) handles most factual questions. Some questions need more: several lookups ("compare A and B"), data from a database ("how many tickets last week?"), or global summaries ("main themes across 2,000 reports"). Advanced patterns handle these — at the price of latency, cost, unpredictability and new security risks.

3Core ideas

Tool calling

  1. You describe tools to the model: name, purpose and a JSON Schema for the arguments.
  2. The model replies with a tool call instead of text, e.g. search_documents({"query": "carry-over limit", "department": "HR"}).
  3. Your code validates the arguments, checks permissions, runs the tool and returns the result as a tool message.
  4. The model continues — another call, or the final answer.
The model never executes anythingYour application does. Every tool call is untrusted input: validate it, allow-list it, enforce the user's permissions, and require human approval for anything with side effects (lesson 23).

Agentic RAG (ReAct loop)

Thoughtwhat do I need?→ Actioncall a tool→ Observationtool result↺ … until done → answer

The model can retrieve several times, refine queries and combine results. Always set limits: maximum steps, time and tokens.

Corrective RAG (CRAG)grade the retrieved documents; if poor, rewrite the query and retrieve again (or abstain)retrieval is often partly relevant
Self-RAGthe model is trained to decide when to retrieve and to critique whether its output is supportedresearch setups; needs specially trained models

GraphRAGextract entities and relations into a knowledge graph, build community summaries, retrieve over the graphglobal, corpus-wide questions; relationship questions. Indexing is expensive.

Routinga classifier sends each question to the right pipelinemixed workloads (documents, metrics, chit-chat)

Model Context Protocol (MCP)

MCP is an open standard for connecting LLM applications to tools and data sources. A server exposes tools, resources and prompts; a client (the AI application) discovers and calls them. It avoids custom glue code for every integration, and it brings the same security concerns as any tool call: permissions, input validation and trust in the server.

5In the real world

  • Start deterministic. Most production RAG is a fixed pipeline plus a few routed special cases. Agents come after evaluation shows multi-step failures you can't fix otherwise.
  • Agents multiply latency and cost: 3–10 LLM calls per question is common.
  • They are harder to test. Evaluate the trajectory (which tools, in which order), not only the final answer.
  • Security risk grows with autonomy — see the OWASP Top 10 for Agentic Applications (lesson 23).

6Common mistakes

  • An agent where a single retrieval call would do.
  • No step, time or token limits, leading to loops and runaway cost.
  • Tools with broad permissions ("run any SQL", "send any email").
  • Text-to-SQL with a writable database connection.

7In our platform

Where this lives

  • The platform starts with a fixed, measurable pipeline. Query rewriting, multi-query, HyDE, decomposition, corrective retrieval and agentic routing are enabled only when evaluation shows a gain.
  • Scope excludes web-search fallback, so "corrective" behaviour here means re-query or abstain.
  • Agentic features would plug into the Query Orchestrator, logging every step as a Langfuse span and storing tool calls with the run.

8Check yourself

Who executes a tool call: the model or your application?
Your application. The model only proposes a call with arguments, and your code must validate and authorize it.
"How many invoices over ₹1 lakh were paid in March?" — vector search or text-to-SQL?
Text-to-SQL (or a structured query) over invoice records. It is an aggregation over structured data, not a semantic lookup.
Why must agents have step and token limits?
Loops and repeated tool calls can run indefinitely, multiplying cost and latency — a form of unbounded consumption.
