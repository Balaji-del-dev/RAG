1What is agentic RAG?

Interview answer — say this first
In simple words

Normal RAG follows a fixed recipe: search once, answer once. In agentic RAG, the LLM decides what to do next — search again, use a different tool, or answer — step by step, until it has enough information. Tool calling is how it asks your code to do something, and GraphRAG is a variant that searches a map of entities and their relationships.

2Why do we need it?

Some questions cannot be answered with one search:

  • Multi-step: "Who approved the policy that replaced the 2024 travel policy?" — first find the new policy, then find who approved it.
  • Multi-source: "Compare our leave policy with the employee survey results" — two different sources.
  • Numbers over records: "How many invoices over ₹1 lakh were paid in March?" — this needs a database query, not text search.

Fixed RAG pipeline

  • Fast, cheap and predictable
  • Easy to test
  • Handles most factual questions

Agentic RAG

  • Handles multi-step, multi-source tasks
  • Slower: 3–10 model calls is common
  • Harder to test and to make safe
Analogy: a fixed recipe vs a chef

A normal RAG pipeline is a fixed recipe. An agent is a chef who decides as they go: "I need the 2026 policy — search. It mentions an approval form — search again. Now I can answer." More flexible, but slower, more expensive and harder to predict.

3How does it work?

How tool calling works

1

Describe the tools to the model

For each tool, give a name, what it does, and a JSON Schema for its arguments.

2

The model asks for a tool call

Instead of plain text, the model replies with a structured request.

Example: search_documents({"query": "carry-over limit", "department": "HR"})
3

Your code checks and runs it

The model never runs anything itself. Your application validates the arguments, checks the user's permissions, and runs the tool.

4

The result goes back to the model

The tool's output is returned as a message. The model then calls another tool or writes the final answer.

The agent loop (ReAct)

Question
Thoughtwhat do I need?
Actiontool call (JSON)
Your code runs itvalidate · authorize
Observationthe result
Final answer
↺ repeat Thought → Action → Observation until done — with limits on steps, time and tokens

Draw the ReAct loop. Always mention the limits.

4Example: step by step

"Who approved the policy that replaced the 2024 travel policy?"
  1. Thought: I need to find which policy replaced the 2024 travel policy.
  2. Action: search_documents({"query": "replaces 2024 travel policy"}) → Observation: "Travel Policy 2026 replaces the 2024 version."
  3. Thought: Now I need the approver of Travel Policy 2026.
  4. Action: search_documents({"query": "Travel Policy 2026 approved by"}) → Observation: "Approved by the CFO on 12 Jan 2026."
  5. Final answer: "The 2026 Travel Policy replaced it [1], and it was approved by the CFO on 12 January 2026 [2]."
Choosing the right tool

"How many invoices over ₹1 lakh were paid in March?" is not a text-search question; it is a count over structured records. A router sends it to a text-to-SQL tool with a read-only database user, a whitelisted set of tables and a row limit, and the generated SQL is validated before it runs.

5Important terms

Agent

An LLM that plans and takes actions with tools in a loop until the task is done.

Tool / function calling

The model outputs a structured request; your code executes it.

ReAct

Reason + Act: the model alternates between thinking and using tools.

Trajectory

The full sequence of steps and tool calls an agent took.

Knowledge graph

Entities (nodes) like people, policies and products, and their relationships (edges).

GraphRAG

RAG over a knowledge graph plus summaries of groups of related entities.

Corrective RAG

Grade the retrieved documents; if they are poor, rewrite the query, search again or abstain.

MCP (Model Context Protocol)

An open standard for connecting AI apps to tools and data. MCP servers expose tools; MCP clients call them.

7Advantages and limitations

Advantages

  • Handles multi-step and multi-source questions
  • Can use databases, APIs and calculators
  • Can retry when the first search is poor
  • GraphRAG answers "big picture" questions

Limitations and risks

  • Higher latency and cost
  • Can loop or take wrong actions
  • Prompt injection can trigger harmful tool use
  • Harder to test: you must evaluate the steps too
Remember — how to control agents

Give the fewest tools and permissions needed, validate every tool call, require human approval for actions that change data, set limits on steps, time and tokens, and log the full trajectory.

In our platform

  • The platform starts with a fixed, measurable pipeline. Agentic routing and corrective retrieval are switched on only when evaluation shows a gain.
  • Web-search fallback is out of scope, so "corrective" behaviour means re-query or abstain.
  • Any agent would run inside the Query Orchestrator, with every step traced in Langfuse.

9How to explain it in an interview

Your 1-minute answer

DefinitionAgentic RAG is an extension of RAG in which the language model acts as an agent that decides, step by step, when to retrieve, which tools to use, and when it has enough evidence to answer.

How it worksIt relies on tool calling: the model outputs a structured request, and the application validates, authorizes and executes it, then returns the result. A ReAct loop repeats thought, action and observation, with limits on steps, time and tokens.

PatternsRelated patterns include corrective RAG, multi-hop retrieval, text-to-SQL for numbers, and GraphRAG, which retrieves over a knowledge graph for corpus-wide and relationship questions.

Trade-offThese handle complex questions but add latency, cost and risk, so I start with a fixed pipeline and add agentic steps only where evaluation shows multi-step failures.

Don't say"The model executes the tools."
Say instead"The model proposes a call; our code validates, authorizes and executes it."
Don't say"We should build an agent for our chatbot from day one."
Say instead"Start with a fixed pipeline and add agentic steps only for failures that evaluation shows need them."
