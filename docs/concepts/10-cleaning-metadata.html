1What are data cleaning and metadata?

Interview answer — say this first
In simple words

Cleaning removes the rubbish from the extracted text: repeated page footers, broken characters and duplicate files. Metadata is a label on every document and chunk — title, page, date, department, version, who may see it — so search can filter and the answer can show the right source.

2Why do we need it?

Noise hurts in two ways: it wastes tokens, and it wins searches it shouldn't. A footer like "Confidential — Company XYZ — Page 4" repeated on every page weakly matches many questions and pushes real answers out of the top results. Without metadata you cannot say "only the 2026 HR policy" or "only documents this user may see".

Without cleaning and metadata

  • Footers and headers pollute search results
  • The same file appears twice in the results
  • Old 2024 and new 2026 rules get mixed in one answer
  • Users may see documents they are not allowed to see

With cleaning and metadata

  • Only real content is indexed
  • One copy of each document
  • Search filters to the current version
  • Access rules are applied during search
Analogy: a well-run library

A library removes damaged copies and duplicates, and puts a label on every book: subject, author, year, shelf. Without labels you can't ask for "only 2026 books on HR". Cleaning = removing damaged copies. Metadata = the label on every chunk.

3How does it work?

1

Normalize the text

Fix broken characters, extra spaces and words split across lines.

Example: "employeeâ€™s" → "employee's" · "infor- mation" → "information"
2

Remove boilerplate

Delete text that repeats on every page and is not real content: headers, footers, page numbers, menus, legal disclaimers.

3

Remove duplicates

Exact duplicates have the same content hash (SHA-256). Near-duplicates are almost the same and are found with MinHash or embedding similarity.

4

Handle versions

If the file is a changed copy of an existing document, store it as a new version and mark the old one as "superseded".

5

Attach metadata to every chunk

Copy document labels (title, version, department, access groups) and add chunk labels (section, page). These become search filters and citation details.

Cleaning a 40-page policy PDF

  2. Join words broken across lines: "infor- mation" → "information".
  3. Remove the line "Confidential — HR — Page N", which repeats on all 40 pages.
  4. The same policy was uploaded twice. Same SHA-256 hash → keep only one.
  5. Add this metadata to every chunk:
{ "title": "Leave Policy", "version": 3, "section_path": "Leave › Carry-over",
  "page_start": 6, "department": "HR", "language": "en",
  "effective_date": "2026-04-01", "access_groups": ["all-employees"] }
How metadata is used at question time

Question: "What is the 2026 travel allowance for managers?" The search adds filters: document_type = policy, department = Finance, effective_date ≥ 2026-01-01. Old 2024 and 2025 versions are excluded automatically, so the answer cannot mix old and new rules.

5Important terms

Normalization

Making text consistent: same character encoding, clean spaces, joined words.

Boilerplate

Repeated text that is not real content: headers, footers, menus, disclaimers.

Exact duplicate

Identical content. Found by comparing a content hash like SHA-256.

Near-duplicate

Almost the same content. Found with MinHash, SimHash or embedding similarity.

Metadata

Labels that describe a document or chunk: title, page, date, version, access.

Metadata filter

A search condition on metadata, such as department = HR.

Metadata enrichment

Adding labels automatically, for example a local model detects the topic or language.

Provenance

Where a chunk came from: document, version, page, parser and pipeline version.

Remember

Keep the original text for citations. Do heavy normalization (lowercasing, stemming) only inside the search index, not in the stored text.

7Advantages and limitations

Advantages

  • More precise search results
  • Fewer wasted tokens
  • Current-version answers only
  • Access control and correct citations

Watch out for

  • Over-cleaning can delete real content
  • Wrong metadata gives wrong filters
  • Near-duplicate detection needs tuning
  • Metadata must stay in sync with the indexes

9How to explain it in an interview

Your 1-minute answer

DefinitionData cleaning removes noise from extracted text, such as repeated headers and footers, broken characters and duplicate documents, so that only meaningful content is indexed. Metadata is structured information attached to each document and chunk, such as title, section, page, date, version and access groups.

HowI normalize the text, remove boilerplate, detect exact duplicates by content hash and near-duplicates by similarity, and treat changed files as new versions. Then I attach metadata to every chunk.

ExampleFor "the 2026 travel allowance", metadata filters on department and effective date exclude older versions, so the answer cannot mix old and new rules.

WhyClean text improves search precision and saves tokens, and metadata enables filtering, current-version answers, citations and access control.

Don't say"Lowercase and strip everything before storing."
