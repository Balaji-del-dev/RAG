1What is document parsing and OCR?

Interview answer — say this first
In simple words

Parsing means reading a file (PDF, Word, Excel, web page) and pulling out its text in the right order, together with its headings, tables and page numbers. OCR is used when the page is only a picture, like a scan: it "reads" the letters from the image.

2Why do we need it?

Every later step — chunking, embeddings, search, the LLM — works on the parsed text. If the parser mixes up two columns or turns a table into a jumble of numbers, nothing later can fix it. This is "garbage in, garbage out".

Bad parsing

  • Two columns read across as one line
  • Table becomes "Plan Basic Pro Price 500 900"
  • Scanned pages give empty text
  • Headers and footers repeated in every chunk

Good parsing

  • Correct reading order
  • Tables kept as rows and columns
  • OCR only for scanned pages
  • Every piece has its page number and section
Analogy: a PDF is a painting of a page

A PDF doesn't store "paragraphs" or "tables". It stores instructions like "draw the letter T at position x=72, y=640". The parser must rebuild the reading order, columns and tables from these scattered letters. A scanned PDF is only a photo, so we need OCR to read the letters.

3How does it work?

1

Check the real file type

Look at the file's content, not just its name, so a renamed program is not treated as a PDF. Reject files that are too big or encrypted.

2

Extract the text layer quickly

Digital PDFs contain real text. A fast tool like PyMuPDF reads it with its position on the page.

3

Check each page: is there enough text?

If a page gives almost no characters, it is probably a scan. Only those pages go to OCR.

4

Run OCR on the pages that need it

Render the page as an image at about 300 DPI and run OCR (Tesseract or EasyOCR).

5

Analyse the layout

A layout tool like Docling finds headings, paragraphs, lists and tables, and builds the correct reading order.

6

Save structured output and check quality

Save text as Markdown or JSON with page numbers and section paths. Check characters per page, OCR confidence and language.

4Example: step by step

A 20-page contract: 18 digital pages + 2 scanned signature pages
  1. Check the file content: it really is a PDF.
  2. PyMuPDF extracts text from all pages in under a second. Pages 19–20 return almost no characters.
  3. Only pages 19–20 are turned into images at 300 DPI and sent to OCR.
  4. Docling finds headings ("Clause 7 — Penalties"), paragraphs and a fee table, and puts them in reading order.
  5. The fee table is kept as a Markdown table with its header row.
  6. Output: structured text with a page number and section for every element, saved as an artifact.

Why tables need special care

Flattened: "Plan Basic Pro Price 500 900 Users 5 20" — the model cannot tell which number belongs to which plan. Kept as a table:

| Plan  | Price (₹) | Users |
|-------|-----------|-------|
| Basic | 500       | 5     |
| Pro   | 900       | 20    |
Remember

For large tables, split them into groups of rows and repeat the header row in every chunk, so every number keeps its meaning.

5Important terms

Text layer

Real, selectable text inside a PDF. Scanned PDFs don't have one.

Born-digital PDF

A PDF created by software (Word, export), so it has a text layer.

OCR (Optical Character Recognition)

Software that reads letters from an image.

DPI

Image resolution. About 300 DPI works well for OCR.

Layout analysis

Finding headings, paragraphs, columns, tables and figures on a page.

Reading order

The correct order to read text blocks, for example down column 1, then column 2.

Table structure recognition

Rebuilding the rows and columns of a table.

Artifact

A saved intermediate output, such as the parser's JSON or OCR text.

7Advantages and limitations

Good parsing gives you

  • Better chunks, better search, better answers
  • Correct page numbers for citations
  • Tables that the LLM can read correctly
  • Scanned documents become searchable

Challenges

  • Multi-column layouts and side notes
  • Complex or merged-cell tables
  • Poor-quality scans and handwriting
  • OCR is slow and less accurate than a text layer
  • Uploaded files can be malicious
SecurityUploaded files are untrusted. Parse them with time, memory, page and size limits; reject encrypted or oversized files; never run macros; and run the parsing workers in isolation.

9How to explain it in an interview

Your 1-minute answer

DefinitionDocument parsing is the process of extracting text and its structure — headings, paragraphs, tables and page numbers — from files such as PDFs, Word documents and web pages. When a page is only an image, OCR is used to recognize the characters.

How it worksI first check the real file type, extract the text layer quickly with PyMuPDF, and send only pages without enough text to OCR at about 300 DPI. A layout tool like Docling then rebuilds the reading order and table structure.

ExampleTables are kept as Markdown tables with the header repeated in each chunk, so a price stays connected to its plan.

Why it mattersParsing quality sets the upper limit for RAG quality, so I measure it, store the parsed artifacts, and treat uploaded files as untrusted.

Don't say"We just run OCR on every PDF."
Say instead"We use the text layer when it exists and OCR only pages without usable text, because OCR is slower and less accurate."
Don't say"Tables are just text."
Say instead"We keep tables as tables, with the header repeated in each chunk, so numbers keep their meaning."
Don't say"Parsing is a solved problem."
Say instead"Parsing quality is often the biggest limit on RAG quality, so we measure it."
