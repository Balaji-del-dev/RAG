2Why it matters

The embedding model decides what "similar" means for your whole system. A weak or wrongly used model (missing prefixes, wrong language, wrong pooling) quietly caps retrieval quality, and no prompt can fix it later. It is also expensive to change: switching models means re-embedding the whole corpus.

3Core ideas

Bi-encoders

query"how many leave days carry over?"→encoder→q-vector · passagechunk text→same encoder→p-vector =similarity

Query and passage are encoded separately, so passage vectors can be computed once and stored. Search is then only fast vector comparisons. Cross-encoders (lesson 17) read the pair together: more accurate, but too slow to apply to a whole corpus.

How they are trained

Contrastive learning on millions of (query, relevant passage) pairs: pull matching pairs together, push non-matching passages apart. Hard negatives — passages that look relevant but aren't — teach fine distinctions. This is why models trained for retrieval beat general sentence-similarity models at search.

Asymmetric search and prefixes

A question is short; a passage is long and declarative. Many models therefore expect a prefix or instruction on queries (and sometimes on passages):

Model family (examples)Convention
E5"query: …" and "passage: …"
Nomic embed"search_query: …" and "search_document: …"
BGE, Qwen3-Embedding, othersan instruction prepended to the query only (see the model card)

4How to choose a model

  1. Shortlist from the MTEB / MMTEB leaderboard, looking at retrieval scores in your languages. Leaderboards are a starting point, not proof.
  2. Check the license. Some top models are non-commercial (for example NV-Embed-v2 and jina-embeddings-v3 are CC-BY-NC).
  3. Check fit: max input tokens, dimensions, model size, CPU vs GPU speed, multilingual support.
  4. Test on your data: run 2–3 candidates on your evaluation set and compare recall@k and MRR (lesson 20).

Examples of open models (2026)

  • Qwen3-Embedding (0.6B / 4B / 8B, Apache-2.0): strong multilingual results; the 0.6B is a good quality-per-VRAM choice.
  • BGE-M3 (MIT, 8K context): dense, sparse and multi-vector outputs from one model — useful for hybrid search.
  • EmbeddingGemma (~300M): small and fast, for CPUs and laptops.
  • E5, Nomic, Snowflake Arctic-Embed families.

Questions to answer

  • Which languages and scripts appear in your documents?
  • How long are your chunks (in model tokens)?
  • CPU only, or GPU? How many chunks per hour?
  • Commercial use allowed?

5In the real world

  • Dimensions trade quality for memory and speed. Matryoshka-trained models let you keep only the first 256 or 512 of 1,024 dimensions with a small quality loss.
  • Normalize vectors (unit length) and use the metric the model was trained with (lesson 03).
  • Batch embedding calls at ingestion, and cache by content hash so unchanged chunks are never re-embedded.
  • Pin the version: model name + exact revision + dimension + prefix convention. Any change means a new index generation.
  • Domain jargon (medical, legal, internal product names) can justify fine-tuning the embedder on your own query-passage pairs (lesson 26).

6Common mistakes

  • Picking the #1 leaderboard model without checking license, size or your languages.
  • Forgetting query and passage prefixes.
  • Chunks longer than the model's max tokens, silently truncated.
  • Upgrading the model "in place" so old and new vectors mix in one index.

8Check yourself

Why can passage embeddings be precomputed but cross-encoder scores cannot?
A bi-encoder encodes each passage independently of any query. A cross-encoder needs the query and the passage together, so it can only run at query time.
What are hard negatives, and why do they matter?
Passages that look relevant but aren't. Training against them teaches the model fine distinctions instead of only topic matching.
You switch to a better embedding model. What must happen to the index?
Re-embed every chunk with the new model into a new collection (a new index generation), validate it, then publish. Old and new vectors must never be mixed.
