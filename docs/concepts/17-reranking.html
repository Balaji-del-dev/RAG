1What is reranking?

Interview answer — say this first
In simple words

First, a fast search finds about 50 possible chunks. Then a slower but much smarter model — the reranker — reads the question and each chunk together, gives each a relevance score, and keeps only the best 5 for the LLM.

2Why do we need it?

Fast search (vectors, BM25) is good at finding roughly relevant chunks, but its order is not precise. The #1 result might be about sick leave when the question is about annual leave. Since we can only send a few chunks to the LLM, the top 5 must be the right 5.

Without a reranker

  • Top results are roughly relevant, not exactly
  • The best chunk may be at rank 12, so it is never sent
  • The LLM gets noisy context

With a reranker

  • The truly relevant chunks move to the top
  • Fewer, better chunks go to the LLM
  • Its score can tell us when to say "I don't know"
Analogy: shortlisting, then interviewing

A company receives 10,000 CVs. A fast filter picks 50 that look relevant (first-stage search). Then a careful interviewer reads each of the 50 next to the job description and picks the best 5 (the reranker). Reading all 10,000 carefully would take too long; the fast filter alone would pick some poor matches.

3How does it work?

1

Take the top candidates from hybrid search

Usually the top 30–50 fused results (lesson 16).

2

Make (question, chunk) pairs

Each pair is given to the reranker as one input. Long chunks are cut to the reranker's limit (often 512 tokens).

3

The cross-encoder scores each pair

Because it reads question and chunk together, every word of the question can attend to every word of the chunk. It understands that "carry over" matches "may be transferred to the following year". All pairs are scored in one batch — tens of milliseconds on a GPU.

4

Sort and keep the best 5–10

Optionally remove near-duplicates with MMR, or expand small chunks to their parent section.

5

Check the best score

If even the best score is below a tested threshold, there is no good evidence. The system abstains instead of guessing (lesson 18).

Two-stage retrieval: recall first (fast and broad), precision second (slow and accurate).

4Example: step by step

Question: "How many annual leave days can I carry over?"
ChunkRank after hybrid searchReranker scoreNew rank
"Sick leave cannot be carried over…"10.214
"Annual leave: up to five days may be transferred to the following year…"40.941
"Carried-over days must be used by 31 March."20.812
"Leave requests are submitted in the HR portal."30.353

The reranker moves the chunk that really answers the question from rank 4 to rank 1.

MMR — Maximal Marginal Relevance

next = argmax over d of [ λ · relevance(q, d) − (1 − λ) · max similarity(d, already selected) ]. MMR picks chunks that are relevant and different from those already chosen, so five copies of the same paragraph don't fill the prompt. λ ≈ 0.5–0.8.

Remember — the recall ceiling

If the correct chunk is at rank 140 but only the top 50 are reranked, the reranker never sees it. Reranking improves the order of what it receives; it cannot find what retrieval missed. Fix recall first.

5Important terms

Reranker

A model that re-orders retrieved candidates by how relevant they really are.

Cross-encoder

Reads the question and a passage together and outputs one relevance score.

Two-stage retrieval

Fast, broad search first, then precise reranking of the top candidates.

Late interaction (ColBERT)

Stores one vector per token and compares them with MaxSim. Between bi- and cross-encoders.

LLM reranker

An LLM judges or orders the candidates. Strong but slow.

MMR

Maximal Marginal Relevance: picks results that are relevant and not repetitive.

7Advantages and limitations

Advantages

  • Much better precision in the top results
  • Fewer chunks needed in the prompt
  • Scores are useful for abstention
  • Easy to add to an existing pipeline

Limitations

  • Adds latency (one run per pair)
  • Only reorders what it receives
  • Long chunks get truncated
  • Needs a GPU for low latency at scale

9How to explain it in an interview

Your 1-minute answer

DefinitionReranking is a second retrieval stage that re-orders the candidates from fast first-stage search according to their true relevance to the query.

How it worksIt usually uses a cross-encoder, a transformer that reads the query and each candidate passage together and outputs a relevance score. This is far more accurate than comparing separate embeddings, but it runs once per pair, so it is applied only to the top 30–50 candidates, and the best 5–10 go to the LLM.

ExampleA chunk about annual-leave carry-over at rank 4 moves to rank 1, above a chunk about sick leave that only shared keywords.

Key pointReranking improves precision but cannot fix poor recall, and its top score is a useful signal to abstain when no good evidence exists.

Don't say"Use the cross-encoder to search the whole corpus."
Say instead"It runs once per pair, so it is used only on the top candidates from fast retrieval."
Don't say"The reranker will fix bad retrieval."
Say instead"It can only reorder what it receives. Recall must be solved first."
