1What is keyword search and BM25?

Interview answer — say this first
In simple words

Keyword search finds chunks that contain the same words as the question. BM25 is the formula that decides which matching chunk is best: rare words count more, repeating a word helps only a little, and long chunks don't win just because they are long.

2Why do we need it?

Embeddings (lesson 03) are great at meaning but weak at exact things: product codes, error numbers, names, invoice IDs. If the user asks about "E-4012", only keyword search reliably finds the document with that exact code.

Keyword search (BM25) is strong at

  • Exact IDs, codes and numbers: "E-4012", "INV-48213"
  • Names and rare technical terms
  • Quoted phrases
  • No model needed; easy to explain

Keyword search is weak at

  • Different words, same meaning ("car" vs "vehicle")
  • Natural, conversational questions
  • Questions in another language
Remember

Keyword search and vector search fail on different questions. That is why production RAG uses both: hybrid search (lesson 16).

3How does it work?

1

Analyze the text

An analyzer splits text into words, lowercases them and reduces them to a root form (stemming). The same analyzer runs on documents and questions, so "carried over" matches "carry over".

Example: "Carried-over Days" → carri · over · day
2

Build an inverted index

For every word, store the list of chunks that contain it — like the index at the back of a textbook.

Example: leave → c12, c48, c91 · carri → c12, c77 · e-4012 → c305
3

Look up the question's words

At search time, analyze the question the same way and look up each word in the index. Only chunks that contain at least one word are candidates — this is very fast.

4

Score the candidates with BM25

BM25 gives each chunk a score using three rules: rare words matter more (IDF), repetition helps but saturates, and length is normalized. The highest scores come first.

The same analyzer is used for documents and questions.

4Example: step by step

The BM25 formula (know the parts, not the maths)

score(q, d) = Σ over query terms t:
    IDF(t) × tf(t,d) × (k1 + 1) / ( tf(t,d) + k1 × (1 − b + b × |d| / avgdl) )
PartMeaning in simple words
IDF(t)inverse document frequency: high for rare words, low for common words like "the"
tf(t, d)how many times the word appears in this chunk
k1 ≈ 1.2how quickly repetition stops adding score (saturation)
b ≈ 0.75how much to adjust for chunk length (0 = ignore length, 1 = full adjustment)
|d| / avgdlthis chunk's length compared with the average chunk length
Real example: "How do I fix error E-4012?"

Vector search returns general troubleshooting pages, because "E-4012" has little meaning for an embedding model. BM25 finds the one runbook that contains the exact code "E-4012", because that word is very rare (high IDF). Combining both gives the exact runbook and related explanations.

How it is used in OpenSearch

  • text fields are analyzed and scored with BM25; keyword fields are stored exactly, for IDs and filters.
  • match = full-text search; match_phrase = words in order; term = exact keyword match.
  • A bool query combines scoring clauses (must, should) with strict filter clauses for access groups and dates.
  • Highlighting returns the matching fragment, useful for citation snippets.

5Important terms

Lexical search

Search by matching words. Also called keyword search or sparse search.

Inverted index

A map from each word to the list of documents that contain it.

Analyzer

The text-processing chain: split into words → lowercase → stemming → stop words.

Stemming

Reducing words to a root form: "carried" → "carri".

IDF

Inverse document frequency: how rare a word is across all documents.

TF-IDF

Term frequency × IDF. The simpler ancestor of BM25.

Keyword field

A field stored exactly as it is, for IDs, filters and sorting.

SPLADE

A learned sparse model that gives weights to words, including related words not in the text.

7Advantages and limitations

Advantages

  • Excellent for exact terms, IDs and codes
  • No GPU or model needed
  • Fast, mature and explainable
  • A strong baseline that is hard to beat on some data

Limitations

  • Misses synonyms and paraphrases
  • Needs a language-specific analyzer
  • Typos can break matches
  • Does not understand meaning or intent

9How to explain it in an interview

Your 1-minute answer

DefinitionLexical search, or keyword search, retrieves documents that contain the query words by using an inverted index, which maps each term to the documents where it appears. BM25 is the standard ranking function for it.

How BM25 scoresIt scores a document higher when query terms appear in it more often, with saturation so repetition helps less and less; when the terms are rare across the collection, using IDF; and it normalizes for document length.

ExampleFor "How do I fix error E-4012?", BM25 finds the exact runbook with that code, while vector search returns general troubleshooting pages.

In practiceBM25 is essential for exact identifiers and names, so production RAG combines it with vector search and fuses the results.

Don't say"Keyword search is outdated now that we have embeddings."
Say instead"BM25 is a strong baseline and essential for exact terms. Production systems combine both."
Don't say"We use a should clause for access rules."
Say instead"Access rules go in a filter clause, which strictly excludes documents that don't match."
