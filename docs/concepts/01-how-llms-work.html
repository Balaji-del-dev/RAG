1What you will learn

  • What a large language model (LLM) actually does: predict the next token.
  • The training stages that turn raw text into a helpful assistant.
  • The difference between base, instruct and reasoning models.
  • Why models hallucinate, and why that is the reason RAG exists.

2Why it matters

Every later lesson builds on one fact: an LLM produces the most likely continuation of the text it is given. It is not a database and it does not look anything up. Once that is clear, prompts, retrieval, citations, guardrails and evaluation all make sense. Each one exists to steer or check that continuation.

3Core ideas

Next-token prediction

An LLM takes a sequence of tokens (pieces of words — lesson 02) and outputs a probability for every token in its vocabulary. The text is then extended one token at a time:

"The capital of France is"→ modelprobabilities→ " Paris" 92%" a" 3% · " located" 2% …→ append, repeat

This is called autoregressive generation: each new token is added to the input and the model runs again. A 500-token answer needs 500 steps.

Parameters are compressed patterns, not records

A "7B" or "70B" model has 7 or 70 billion learned numbers (parameters or weights). Training adjusts them so the model predicts text well. Knowledge ends up spread across these numbers in a lossy, statistical way, like a person's memory rather than a filing cabinet. So the model:

  • cannot tell you where it learned something (no built-in citations),
  • knows nothing after its knowledge cutoff date, and nothing about your private files,
  • can produce fluent, confident text that is wrong.

Training stages

StageWhat happensResult
1. Pre-trainingPredict the next token on trillions of tokens of web pages, books and code. No labels needed (self-supervised).Base model: continues text, but does not follow instructions well.
2. Supervised fine-tuning (SFT)Train on many examples of instruction → good response.Follows instructions and chat format.
3. Preference tuningRLHF or DPO: learn from human or AI rankings of which answer is better.Instruct / chat model: helpful, safer, better style.
4. Reasoning training (some models)Reinforcement learning on problems with checkable answers (math, code), rewarding long step-by-step thinking.Reasoning model: "thinks" before answering. Slower, uses more tokens, better on hard problems.

The context window

The context window is the maximum number of tokens the model can see at once: system prompt + conversation + retrieved documents + its own answer. Anything not in the context does not exist for the model during that request. RAG works by putting the right text into this window.

4How it works, end to end

  1. Tokenize the text into token IDs (lesson 02).
  2. Embed: each ID becomes a vector of numbers (lesson 03).
  3. Transformer layers mix information between tokens using attention (lesson 04).
  4. The last layer produces logits, one score per vocabulary token. Softmax turns them into probabilities.
  5. Decode: pick a token using temperature, top-p and similar settings (lesson 05). Append it and repeat until a stop condition.

Why hallucinations happen

Training rewards plausible text, not true text. If the model has never seen the answer, the most likely continuation is still something fluent that looks like an answer. Instruction tuning reduces this but cannot remove it. The practical fix is to give the model the facts in the context and check that its answer is supported by them. That is retrieval-augmented generation (lesson 08) plus grounding checks (lesson 18).

5In the real world

  • Open-weight models can run on your own hardware: families such as Llama, Qwen, Mistral, Gemma, DeepSeek and gpt-oss. Each family ships several sizes. Always use the instruct version for chat and RAG.
  • Size vs hardware: an 8B model fits a single consumer GPU when quantized; 70B needs a large GPU or several (lesson 06).
  • Licenses differ. Some open-weight models restrict commercial use or require attribution. Check before choosing.
  • Small model + good retrieval often beats a large model without retrieval on questions about your own documents.
Real-world ruleUse the model for language (understanding, summarizing, phrasing, reasoning over given text). Use retrieval and databases for facts.

6Common mistakes

  • Asking the model about facts it cannot know (your files, recent events) without giving them in the context.
  • Trusting confident wording as a sign of correctness.
  • Using a base model for chat — it will ramble or continue your question instead of answering it.
  • Choosing the biggest model first instead of the smallest model that passes your evaluation (lesson 20).

8Check yourself

Why can an LLM give a confident but wrong answer?
It is trained to produce likely text, not verified facts. When the true answer is missing from its training data or context, the most likely continuation is still fluent and answer-shaped.
What is the difference between a base model and an instruct model?
A base model only continues text (pre-training). An instruct model has extra training (SFT plus preference tuning) to follow instructions and hold a conversation.
A document was uploaded yesterday. Why can't the model answer questions about it on its own?
The model's knowledge is fixed at training time, and it never saw your private files. The text must be retrieved and placed in the context window for each request.
Why does a 500-token answer take longer than a 50-token answer?
Generation is autoregressive: one forward pass per output token, so time grows with the length of the answer.
