1What you will learn

  • What an embedding is: meaning represented as a list of numbers (a vector).
  • How similarity is measured: cosine similarity, dot product and distance.
  • What embeddings capture well, and what they miss.
  • How dimensions affect memory, and why vectors from different models never mix.

2Why it matters

Semantic search, clustering, deduplication and recommendations all rely on one idea: texts with similar meaning get vectors that point in similar directions. In RAG, the question and every chunk become vectors, and "relevant" means "nearby". Embeddings also live inside every LLM, as the first step of reading tokens (lesson 04).

3Core ideas

An embedding is a point in a high-dimensional space

An embedding model turns text into a fixed-length vector, typically 384 to 4,096 numbers. No single number has a human meaning. Together they place the text in a space where related meanings are close.

From word vectors to contextual embeddings

  • Static word vectors (word2vec, GloVe, around 2013–2014): one vector per word, so "bank" (river) and "bank" (money) share a vector.
  • Contextual embeddings (transformers): each token's vector depends on the words around it. A sentence embedding pools these token vectors, usually by averaging them or using a special token, into one vector for the whole text.

Measuring similarity

MeasureFormulaNotes
Cosine similaritya·b / (|a| |b|)Angle only, from −1 to 1. The most common choice for text.
Dot productΣ aᵢ bᵢEqual to cosine when vectors are normalized to length 1. Fastest to compute.
Euclidean (L2) distance√Σ (aᵢ − bᵢ)²Smaller is closer. For unit vectors it ranks the same as cosine.
Practical ruleNormalize embeddings to length 1 at write time. Cosine, dot product and L2 then give the same ranking, and dot product is the cheapest.

4How it works in retrieval

  1. At ingestion, embed every chunk once and store the vector with the chunk ID (lessons 12–13).
  2. At query time, embed the question with the same model.
  3. Find the stored vectors with the highest similarity: the nearest neighbours.
  4. Return their chunks as candidates for reranking and the prompt.

What embeddings capture — and miss

Good at

  • paraphrases ("reset password" ≈ "forgot my login")
  • topic and intent
  • cross-lingual matching (multilingual models)

Weak at

  • exact IDs, codes, part numbers (E-4012)
  • rare names and new jargon
  • negation and numbers ("not allowed", "> 50 kg")

That is why production systems pair dense vectors with keyword search (BM25). Lessons 14 and 16 cover this.

5In the real world

  • Memory: vectors × dimensions × 4 bytes (float32). One million chunks × 1,024 dims ≈ 4 GB, before index overhead. Quantization shrinks this (lesson 13).
  • Scores are not probabilities. A cosine of 0.78 can be "very relevant" for one model and "unrelated" for another. Tune thresholds per model, using your evaluation set.
  • Models are not interchangeable. Vectors from two different models — or two revisions of the same model — live in different spaces. Changing the model means re-embedding everything.
  • The same embeddings also power deduplication (near-identical chunks), clustering (topic maps) and semantic caching (lesson 25).

6Common mistakes

  • Embedding queries with a different model, revision or prefix than the documents.
  • Using a hard-coded similarity threshold copied from another model.
  • Relying on dense search alone for IDs, error codes and names.
  • Forgetting normalization, then using dot product as if it were cosine.

8Check yourself

Why must the query be embedded with the same model as the documents?
Each model defines its own vector space. Vectors from different models (or revisions) are not comparable, so similarity scores between them are meaningless.
How much raw memory do 2 million vectors of 768 dimensions need in float32?
2,000,000 × 768 × 4 bytes ≈ 6.1 GB, plus index overhead.
A user searches for "error E-4012" and dense search returns generic error pages. Why?
Exact codes carry little semantic meaning for embedding models. BM25 keyword search matches the exact token and should be combined with dense search.
