1What is an embedding?

Interview answer — say this first
In simple words

An embedding turns a sentence into a list of numbers that describes its meaning. Sentences with similar meaning get similar numbers. So the computer can find "related" text by comparing numbers, even when the words are different.

2Why do we need it?

Normal keyword search only finds text that contains the same words as the question. But people use different words for the same idea.

Keyword search only

  • "I forgot my login" does not match "Reset your password"
  • "car" does not match "vehicle"
  • A question in Hindi does not match an English document

With embeddings (semantic search)

  • "I forgot my login" matches "Reset your password"
  • Synonyms and paraphrases are found
  • Multilingual models can match across languages
Analogy: map coordinates for meaning

On a map, two numbers (latitude and longitude) place a city, and nearby cities are close together. An embedding places a sentence on a "map of meaning". Instead of 2 numbers it uses hundreds (usually 384 to 4,096), so it can capture topic, intent, tone and language at once.

3How does it work?

1

Turn every document chunk into a vector

An embedding model reads each piece of text and outputs a vector: a fixed-length list of numbers. We store these vectors in a vector database.

Example: "Steps to change your login password" → [0.85, 0.15, 0.25, …]
2

Turn the user's question into a vector

The question is embedded with the same model, so it lands on the same "map".

Example: "How do I reset my password?" → [0.9, 0.1, 0.2, …]
3

Measure how close the vectors are

We compare the question vector with the stored vectors, usually with cosine similarity. It measures the angle between two vectors: 1 means the same direction (same meaning), 0 means unrelated.

4

Return the closest chunks

The chunks with the highest similarity are the most related in meaning. These are called the nearest neighbours.

4Example: step by step

Which chunk best answers "How do I reset my password?"
  1. Question vector: q = [0.9, 0.1, 0.2] (real vectors are much longer).
  2. Chunk A, "Steps to change your login password": [0.85, 0.15, 0.25]. Chunk B, "Office opening hours": [0.1, 0.9, 0.3].
  3. Cosine similarity = (q · d) ÷ (length of q × length of d). For A: 0.9×0.85 + 0.1×0.15 + 0.2×0.25 = 0.83 → cosine ≈ 0.996. For B: 0.9×0.1 + 0.1×0.9 + 0.2×0.3 = 0.24 → cosine ≈ 0.27.
  4. A is much closer to the question, so A is returned first.

Try it: cosine similarity calculator

Type two vectors with the same number of values. Similar vectors give a value close to 1.

5Important terms

Vector

An ordered list of numbers, such as [0.12, −0.53, 0.88].

Dimension

How many numbers are in the vector. Common sizes are 384, 768 and 1,024.

Embedding model

A model that turns text into a vector (lesson 12).

Cosine similarity

The cosine of the angle between two vectors. 1 = same direction, 0 = unrelated.

Dot product

Multiply matching numbers and add them up. It equals cosine when both vectors have length 1.

Normalization

Scaling a vector so its length is 1. After this, the dot product and cosine give the same result.

Semantic search

Search by meaning using embeddings, instead of by exact words.

Nearest neighbours

The stored vectors that are closest to the question vector.

Remember

Dense and sparse search are good at different things. That is why real RAG systems use both together: hybrid search (lesson 16).

7Advantages and limitations

Advantages

  • Finds text by meaning, not exact words
  • Handles synonyms, paraphrases and typos
  • Can work across languages
  • Fast to compare millions of vectors with a vector index

Limitations

  • Weak at exact IDs, codes, numbers and rare names
  • Often misses negation ("not allowed" vs "allowed")
  • Vectors from different models cannot be compared
  • Scores like 0.8 are not percentages; thresholds must be tested

Real example: support-ticket search

A support team embeds every old ticket. When a new ticket arrives, the system finds the 5 most similar old tickets and shows how they were solved, even if the customer used different words. The same vectors also find duplicate tickets and group tickets by topic.

In our platform

  • Every chunk gets a row in embedding_records with the model name, model version, dimension and Qdrant point ID.
  • One Qdrant collection holds vectors from one model only. A new model means re-embedding everything into a new index generation.
  • The question is always embedded with the same model as the published index.

9How to explain it in an interview

Your 1-minute answer

DefinitionAn embedding is a numerical vector, a fixed-length list of numbers, that represents the meaning of a piece of text. An embedding model is trained so that texts with similar meaning get vectors that are close together.

How it worksWe embed every document chunk and store the vectors. At question time we embed the question with the same model and compare it with the stored vectors using cosine similarity. The closest chunks are the most relevant.

Example"I forgot my login" and "Reset your password" share no words, but their vectors are very close, so semantic search finds the right document.

LimitationEmbeddings are weak at exact codes, IDs and numbers, so in production we combine them with keyword search like BM25.

Don't say"A cosine of 0.8 means 80% relevant."
Say instead"Scores are relative and depend on the model. Thresholds must be tested on an evaluation set."
Don't say"We can switch to a better embedding model without re-indexing."
Say instead"Each model has its own vector space. A new model means re-embedding all chunks."
Don't say"Vector search is enough for everything."
Say instead"Embeddings miss exact IDs and codes, so we combine them with BM25 in hybrid search."
