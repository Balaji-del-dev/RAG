4Build order

  1. Configuration and registry models (pipeline, component and model definitions). Re-read 06, 07.
  2. Upload, validation, hashing, versioning into MinIO + PostgreSQL. Re-read 09, 10, 23.
  3. Jobs: outbox, Celery, retries, step runs. Re-read 25.
  4. Parsing, OCR, normalization, chunking, embeddings. Re-read 09–12.
  5. Qdrant and OpenSearch indexing, generations, validation, publication. Re-read 13, 14, 25.
  6. Hybrid retrieval, RRF, reranking. Re-read 15–17.
  7. Grounded generation, citations, abstention, validation. Re-read 05, 07, 18.
  8. Evaluation and tracing, then guardrails and security hardening. Re-read 20–24.

6Hands-on projects

1 · Baseline in a weekend

20–50 real PDFs → PyMuPDF → recursive chunks → one embedding model → Qdrant → a local LLM. Write 30 questions with expected pages. Measure recall@5.

2 · Make retrieval hybrid

Add OpenSearch BM25 and RRF. Re-measure. Note which question types improved (IDs? names?).

3 · Add a reranker

Rerank the top 50. Compare MRR and nDCG@5, and the added latency.

4 · Grounding and abstention

Add a citation schema and validation, plus 10 unanswerable questions. Measure faithfulness and abstention accuracy.

5 · Break it on purpose

Upload a document with hidden injected instructions and test your defences. Try cross-user retrieval with access groups.

6 · Ship it

Add tracing, a latency budget, outbox-based jobs and blue-green index publication.

7Where to go next

  • Revisit lessons 19 and 26 once the baseline is stable and evaluation shows what is still failing.

8Check yourself

A user says "the answer is wrong". Walk through your first four checks.
(1) Find the trace by request ID. (2) Was the right chunk retrieved, and at what rank, by dense or BM25? (3) Did it reach the prompt after rerank and assembly? (4) Did the model use it, and did validation pass? Then add the case to the evaluation set.
You want to switch to a better embedding model. List the steps.
New model_definitions revision → new pipeline version → re-embed all chunks into a new index generation → validate (counts + evaluation set) → compare with baseline → approve → publish → keep the old generation for rollback.
