1What is a token?

Interview answer — say this first
In simple words

A model does not read words or letters. It reads small pieces of text called tokens. Common words are one token; rare or long words are split into a few tokens. Tokenization is the step that cuts the text into these pieces and gives each piece a number.

2Why do we need tokens?

A neural network can only work with numbers, so text must be turned into numbers first. There are three ways to do it:

One number per word

The list of all words would be endless: names, spelling mistakes, new words, code. Any word not in the list cannot be read.

One number per letter

Every text becomes very long, so the model is slow and can see much less text at once.

One number per sub-word piece (tokens) ✓

The balance. A fixed list of about 32,000–200,000 pieces can build any text, and common words still need only one piece. This is what every modern LLM uses.

Remember — the rule of thumb

In English, 1 token ≈ 4 characters ≈ ¾ of a word. So 1,000 words ≈ 1,300 tokens.

3How does tokenization work?

1

Cut the text into pieces

The tokenizer splits the text into pieces that exist in its fixed list, called the vocabulary. The space before a word is usually part of the token.

Example: "Unbelievable prices!" → Un believ able ␣prices !
2

Replace each piece with its number

Every token in the vocabulary has a fixed number called a token ID. The model only ever sees these numbers.

Example: Un believ able ␣prices ! → [1844, 32291, 481, 7729, 0]
3

The model reads the IDs and predicts the next ID

The IDs go into the model (lesson 01). The model's output is also a token ID.

4

Turn the output IDs back into text

The tokenizer looks up each output ID and joins the pieces back into readable text. This is called decoding.

Text"Unbelievable prices!"
Tokenizeruses the vocabulary
TokensUn · believ · able · ␣prices · !
Token IDs[1844, 32291, 481, 7729, 0]
Modelworks only with numbers

Text → pieces → numbers. Every model family has its own tokenizer and vocabulary.

How is the vocabulary built? (BPE)

Most LLMs build their vocabulary with BPE (Byte-Pair Encoding). The idea: start with single letters and keep joining the pair that appears most often.

Example: learning from the words "low", "lower", "lowest"
  1. Start with single letters: l o w, l o w e r, l o w e s t.
  2. The pair l+o appears most often, so join it into a new token lo.
  3. Now lo+w is the most common pair, so join it into low. "low" is now one token.
  4. Repeat this thousands of times (e+r → er, …) until the vocabulary reaches its target size.
  5. To tokenize new text later, apply the same joins in the same order.

5Important terms

Vocabulary

The fixed list of all tokens a model knows. Usually 32,000 to 200,000 tokens.

Token ID

The number given to a token in the vocabulary. The model works only with these IDs.

Tokenizer

The tool that turns text into token IDs and turns IDs back into text.

BPE (Byte-Pair Encoding)

A way to build the vocabulary by repeatedly joining the most frequent pair of pieces.

Special tokens

Control tokens with a special meaning, such as "start of text", "end of text" or "this is the system message".

Chat template

The exact format, with special tokens, that a chat model expects for system, user and assistant messages.

Prefill and decode

Prefill reads all input tokens at once (fast). Decode writes output tokens one by one (slow).

Truncation

Cutting off text that is longer than a model's token limit. It often happens silently.

7Advantages and limitations

Advantages of sub-word tokens

  • Can represent any text: names, typos, code, emojis
  • Small, fixed vocabulary
  • Common words still need just one token
  • No "unknown word" problem with byte-level BPE

Limitations

  • Non-English languages need more tokens
  • Numbers, dates and IDs split into odd pieces, so exact maths is hard
  • Every model has a different tokenizer, so counts differ
  • Text over a token limit is cut off silently

Real example: the silent truncation bug

A team sets the chunk size to "2,000 characters". Their embedding model can only read 512 tokens. English chunks are about 450 tokens and fit. But Tamil chunks are about 1,100 tokens, so more than half of each Tamil chunk is never embedded, and questions about those parts find nothing. The fix: measure chunk size in tokens, using the embedding model's own tokenizer.

from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("path/to/local/embedding-model")
n_tokens = len(tok.encode(chunk_text, add_special_tokens=False))

9How to explain it in an interview

Your 1-minute answer

DefinitionA token is the basic unit of text that a language model reads and generates, usually a word, part of a word or a punctuation mark. Tokenization splits text into these units using a fixed vocabulary and maps each one to a numeric ID.

How it worksMost models build their vocabulary with Byte-Pair Encoding, which starts from characters and repeatedly merges the most frequent pairs. In English, one token is about four characters, or three quarters of a word.

Why it mattersThe context window, the cost and the speed are all measured in tokens. Output tokens are generated one by one, so long answers are slow, and embedding models silently cut off text above their token limit.

Practical tipThat is why I always count tokens with the tokenizer of the exact model I use, and I keep space in the context window for the answer.

Don't say"A token is a word."
Say instead"A token is a sub-word piece. On average it is about ¾ of an English word."
Don't say"A long prompt is what makes responses slow."
Say instead"Output tokens are generated one by one, so answer length usually decides the latency."
Don't say"All models use the same tokenizer."
Say instead"Each model family has its own. I count tokens with the tokenizer of the model I use."
