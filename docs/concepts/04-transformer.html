2Why it matters

Every model in a RAG system is a transformer: the LLM that writes the answer, the embedding model that finds chunks, and the cross-encoder that reranks them. Understanding attention explains real engineering limits: why context windows are finite, why long prompts are slow and use GPU memory, and why rerankers are more accurate but slower than embedders.

A model stacks the same block many times: around 32 layers for an 8B model and 80 for a 70B model. Each layer refines every token's vector using information from the tokens around it.

Self-attention in plain words

In "I sat on the bank of the river", the vector for bank needs information from river. Attention lets every token ask a question and gather relevant information from other tokens:

  • Query (Q) — what this token is looking for.
  • Key (K) — what each token offers, used to match against queries.
  • Value (V) — the information a token passes on when it is attended to.

Q, K and V are three learned projections of each token's vector. Matching every query against every key gives attention weights. Each token's new vector is a weighted mix of the values.

The formula

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k  +  mask ) · V
  • Q·Kᵀ: similarity of every query with every key, an n × n matrix for n tokens.
  • ÷ √d_k: keeps the scores in a reasonable range, so softmax does not saturate as dimensions grow.
  • mask: in decoder models, a causal mask blocks attention to future tokens, so the model can only use the past.
  • softmax: turns scores into weights that sum to 1.

Multi-head attention

Attention runs in parallel in several heads (for example 32). Each head learns different relations — syntax, references, positions, topics. The results are concatenated and mixed again.

Positions

Attention by itself ignores word order, so position information is added. Modern LLMs use RoPE (rotary position embeddings), which rotates Q and K by an angle that depends on position. Context-extension methods stretch these angles so a model can handle longer inputs.

Prefill, decode and the KV cache

  1. Prefill: the whole prompt is processed in one parallel pass, and keys and values are computed for every token in every layer.
  2. Decode: for each new token, only that token's Q, K and V are computed. Its query attends to all stored keys and values.
  3. The stored keys and values are the KV cache. It trades memory for speed, because nothing is recomputed.
Real numbers: Llama-3-8B32 layers × 8 KV heads × 128 head dimension × 2 (K and V) × 2 bytes (fp16) = 128 KB per token. An 8,192-token context uses about 1 GB of GPU memory per sequence. Ten concurrent users with long prompts need about 10 GB just for the cache. This is why context length and concurrency are capacity decisions.

Why long context is expensive

Attention compares every token with every other token: compute grows with n² during prefill, and KV memory grows with n per sequence. Doubling the context roughly quadruples attention compute. Long prompts also degrade quality ("lost in the middle", lesson 18).

5In the real world: modern improvements

GQA (grouped-query attention)

Several query heads share one key/value head, which shrinks the KV cache 4–8× with little quality loss. Used in Llama 3, Qwen and others.

FlashAttention

Computes exact attention in GPU-friendly tiles, so it is much faster and uses far less memory. Standard in serving engines.

Mixture of Experts (MoE)

The feed-forward layer is split into many "experts" and only a few run per token. A big model at the speed of a small one, but all weights must still fit in memory.

Sliding-window & hybrid attention

Some layers attend only to recent tokens, cutting cost on long inputs.

PagedAttention

vLLM stores the KV cache in pages like virtual memory, so many requests share a GPU efficiently (lesson 06).

Prefix caching

Reuse the KV cache of a shared prompt prefix (system prompt, instructions) across requests. This saves prefill time (lesson 25).

6Common mistakes

  • Setting a huge context window "just in case". It reserves GPU memory and lowers concurrency.
  • Assuming a model handles its advertised maximum context equally well everywhere. Quality usually drops toward the limit.
  • Comparing an embedder (one vector per text) with a cross-encoder (scores a query-passage pair) as if they did the same job.
  • Forgetting that an MoE model needs memory for all experts, not just the active ones.

8Check yourself

What do Q, K and V do in attention?
The query says what a token is looking for, keys are matched against queries to get weights, and values are the information mixed into the token's new vector according to those weights.
Why divide by √d_k?
Dot products grow with vector dimension. Without scaling, softmax becomes extremely peaked, gradients vanish and training becomes unstable.
Why does a decoder model use a causal mask?
During generation the model can only see previous tokens. The mask enforces this in training too, so each position learns to predict the next token from the past only.
Which model type is a cross-encoder reranker, and why is it slower than an embedder at query time?
It is usually an encoder that reads the query and the passage together. It must run once per candidate pair at query time, whereas embeddings of passages are computed once in advance.
What does the KV cache trade?
GPU memory for speed: keys and values of past tokens are stored instead of recomputed for every new token.
