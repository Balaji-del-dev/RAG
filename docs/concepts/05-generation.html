1What is decoding?

Interview answer — say this first
In simple words

At every step, the model gives a list of possible next tokens with probabilities. Decoding is the rule that picks one of them. Settings like temperature and top-p decide whether the model plays safe (always picks the top choice) or takes more risks (sometimes picks a less likely token).

2Why do we need it?

The model does not output a word. It outputs probabilities, for example: "30 days" 58%, "14 days" 26%, "60 days" 12%. Someone must choose. The same model with the same prompt can give careful or creative answers depending only on these settings.

Low temperature (focused)

  • Almost always picks the most likely token
  • Consistent, factual answers
  • Best for RAG, extraction, classification

High temperature (creative)

  • Often picks less likely tokens
  • More variety, more surprises
  • More risk of made-up details
Analogy: choosing a restaurant

Greedy = always go to the #1 rated place. Temperature = how adventurous you feel today. Top-k = only consider the top 5 places. Top-p = consider the best places until together they have 90% of all the votes.

3How does it work?

1

The model gives raw scores (logits)

For every token in the vocabulary, the model outputs a raw score called a logit. Higher = more likely.

Example: "30 days" 3.2 · "14 days" 2.4 · "60 days" 1.6 · "the warranty" 0.4
2

Divide the scores by the temperature

Temperature below 1 makes the gaps between scores bigger (more focused). Above 1 makes them smaller (more random).

3

Softmax turns scores into probabilities

The scores become probabilities that add up to 100%.

4

Filter with top-k or top-p

Top-k keeps only the k most likely tokens. Top-p keeps the smallest group of top tokens whose probabilities add up to p (for example 90%). Unlikely "junk" tokens are removed.

5

Pick one token

Greedy takes the top token. Sampling picks randomly, following the probabilities. The chosen token is added to the text, and the loop continues (lesson 01).

Other settings you must know

max_tokens

The hard limit on answer length. Too low → answers and JSON get cut off.

Stop sequences

Text that ends the output immediately, for example "\nQuestion:".

Repetition penalties

Lower the chance of repeating the same tokens, to stop loops.

Seed

Fixes the randomness so a test gives the same output again.

Streaming

Send each token to the user as soon as it is made. The answer feels fast. The key number is time to first token (TTFT).

How to get reliable JSON output

  1. Ask for it in the prompt and show an example. This works most of the time.
  2. JSON mode: the server guarantees the output is valid JSON.
  3. Constrained decoding with a JSON Schema: at every step, tokens that would break the schema are blocked. The output always has the right structure.
  4. Always validate in code (for example with Pydantic). Repair once, or fail clearly.

5Important terms

Logits

The raw scores for every token, before softmax.

Softmax

Turns scores into probabilities that add up to 1.

Greedy decoding

Always pick the most likely token.

Sampling

Pick a token randomly, following the probabilities.

Temperature

Divides the logits before softmax. Lower = more focused; higher = more random.

Top-k

Keep only the k most likely tokens.

Top-p (nucleus sampling)

Keep the smallest set of top tokens whose probabilities add up to p.

Beam search

Keep several best partial answers at once. Used for translation, rarely for chat.

Constrained decoding

Block any token that would break a schema or grammar.

TTFT

Time to first token: how long the user waits before the answer starts.

7Advantages and limitations

Why these settings help

  • One model can be careful or creative, without retraining
  • Low temperature makes RAG answers consistent
  • Top-p removes junk tokens
  • Constrained decoding guarantees valid JSON

Things to watch

  • Temperature 0 is still not 100% identical every time
  • High temperature increases hallucination
  • Too-low max_tokens cuts answers off
  • Settings that work for one model may not suit another

Real example: a policy bot giving different answers

Users complain that the HR bot gives a different leave number each time they ask. The team finds the temperature is set to 1.0. They lower it to 0.1, add citations, and the answers become consistent and match the policy.

9How to explain it in an interview

Your 1-minute answer

DefinitionDecoding is the process by which a language model selects each next token from the probability distribution it predicts.

How it worksThe model outputs logits, which are divided by the temperature and converted into probabilities with softmax. Top-k or top-p then removes unlikely tokens, and one token is selected, either greedily or by sampling.

ExampleWith low temperature, "30 days" goes from 58% to 80%, so the model almost always picks it. With high temperature, the less likely options are chosen more often.

In practiceFor a factual RAG assistant I use a low temperature, around 0 to 0.3, with top-p around 0.9, enough max_tokens, and schema-constrained JSON output that is validated in code.

Don't say"Temperature 0 is always 100% deterministic."
Say instead"It is greedy, but GPU batching and floating-point order can still cause small differences."
Don't say"Higher temperature makes the model smarter."
Say instead"It only makes the choice more random: more variety and more risk of errors."
Don't say"We just ask for JSON and parse it."
Say instead"We use constrained decoding or JSON mode, and always validate against a schema."
