2Why it matters

The same model and prompt can give a careful factual answer or a creative, unreliable one, depending only on the decoding settings. For RAG you want focused, repeatable, well-formed answers, and that is mostly a matter of choosing these settings deliberately and recording them.

3Core ideas

From logits to a token

The model outputs a score (logit) for every vocabulary token. Softmax converts the scores to probabilities. A decoding strategy then picks one token:

  • Greedy: always take the most likely token. Deterministic, but it can get repetitive.
  • Sampling: draw a token at random according to the probabilities, after reshaping them with the settings below.
  • Beam search: keep several candidate sequences. Used for translation; rarely for chat.

4How it works in an application

Streaming

Tokens are sent to the browser as they are generated, using Server-Sent Events (SSE) or WebSockets. Total time is unchanged, but users see the answer start quickly. The key latency metric becomes time to first token (TTFT).

Structured output

  1. Ask for JSON in the prompt and show an example. Simple, but it fails sometimes.
  2. JSON mode: the server guarantees syntactically valid JSON.
  3. Schema-constrained decoding: at each step, tokens that would break a given JSON Schema or grammar are masked out. Examples: llama.cpp grammars, vLLM guided decoding, Ollama's structured outputs. The output always parses.
  4. Always validate the result (for example with Pydantic) and decide what to do on failure: repair once or fail.

Reasoning models

Reasoning models write hidden or visible "thinking" tokens before the answer. Expect higher latency and token usage. Some servers let you set a thinking budget or switch thinking off. For short factual RAG answers, a non-reasoning instruct model is often enough and much faster.

5In the real world

  • Factual RAG: temperature 0–0.3, top-p about 0.9, a sensible max_tokens and a schema for the answer. Creativity is a bug here.
  • Temperature 0 is not perfectly deterministic on GPUs. Batching and floating-point order can still change outputs slightly. Fix seeds and settings for evaluation, but compare results on many cases, not one.
  • Record every setting with each answer so results can be reproduced and compared.
  • Truncated JSON is the classic symptom of a max_tokens that is too low.

6Common mistakes

  • High temperature for factual question answering.
  • Changing temperature and top-p together, then not knowing which one helped.
  • Parsing model JSON without validation, or without a schema.
  • Not streaming, so users stare at a spinner for 5–10 seconds.

8Check yourself

What happens to the probabilities when temperature goes from 1.0 to 0.2?
The distribution becomes much sharper: the top token gets most of the probability and unlikely tokens almost disappear. Output becomes more predictable.
Top-p = 0.9 — which tokens remain?
The smallest group of most likely tokens whose probabilities add up to at least 90%. The long tail of unlikely tokens is removed before sampling.
Your JSON answers sometimes end with "citations": [1, . What is the likely cause?
The answer hit max_tokens. Raise the limit, shorten the requested output, and validate so truncated JSON is caught.
