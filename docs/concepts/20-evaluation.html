1What is RAG evaluation?

Interview answer — say this first
In simple words

RAG evaluation means giving the system the same test questions every time you change something, and measuring two things: did it find the right documents, and did it answer correctly from them? Then you compare the scores with the previous version before releasing.

2Why do we need it?

A RAG system has many settings: parser, chunk size, embedding model, top-k, reranker, prompt, LLM. A change that helps some questions often hurts others. Without measurement, decisions are based on "it looks better", and problems reach users unnoticed.

Without evaluation

  • "We tried a few questions and it looked fine"
  • No idea which change broke what
  • Regressions found by users

With evaluation

  • Fixed test set, numbers for every change
  • Retrieval and generation measured separately
  • Release only when the scores pass
Analogy: an exam with an answer key

You can't know whether a student improved without giving the same exam before and after. A golden dataset is that exam: questions with known correct sources and answers. After every change the system takes the exam again, and you compare the marks — per question, not just the total.

3How does it work?

1

Build a golden dataset

Collect realistic questions with their expected sources (document + page) and, where possible, expected answers. Include hard cases: tables, IDs, multi-part questions, other languages, and questions the documents cannot answer.

2

Run the current system to get a baseline

Run every question and save the results and scores.

3

Measure retrieval

Did the expected chunks appear in the top k? Use recall@k, MRR and nDCG.

4

Measure generation

Is every claim supported by the context (faithfulness)? Does the answer address the question (relevancy)? Are citations correct? Did it abstain when it should?

5

Make one change, compare, decide

Change one thing, run again, compare per metric and per question, and inspect the cases that got worse. Release only if the agreed thresholds pass.

4Example: step by step

Retrieval metrics

MetricQuestion it answers
Hit rate@kIs at least one relevant chunk in the top k?
Recall@kWhat share of all relevant chunks is in the top k?
Precision@kWhat share of the top k is relevant?
MRRHow high is the first relevant result? (average of 1 ÷ rank)
nDCG@kAre the relevant results near the top? (position-weighted)
Worked example

3 chunks are relevant. The top 5 results are: not relevant, relevant, not relevant, relevant, not relevant. So hit@5 = 1, recall@5 = 2 ÷ 3 = 0.67, precision@5 = 2 ÷ 5 = 0.40, and MRR = 1 ÷ 2 = 0.50 (the first relevant result is at rank 2).

Try it: retrieval metrics for one question

Generation metrics

MetricMeaning
Faithfulness (groundedness)share of claims supported by the retrieved context
Answer relevancydoes the answer address the question?
Answer correctnessdoes it match the expected answer?
Context precision / recallwas the context relevant, and did it contain what was needed?
Citation precision / coveragedo citations support their sentences, and is every claim cited?
Abstention accuracyabstains on unanswerable questions, answers answerable ones
Real example: reading the numbers

After a change, recall@10 stays at 0.92 but faithfulness drops from 0.95 to 0.86. Retrieval is fine; generation got worse — probably the new prompt or model. The team reverts the prompt change and investigates the 14 questions that got worse.

5Important terms

Golden dataset

A reviewed set of test questions with expected sources and answers. Versioned and fixed.

Baseline

The current system's scores, used for comparison.

Recall@k

The share of all relevant chunks that appear in the top k results.

MRR

Mean Reciprocal Rank: the average of 1 ÷ (rank of the first relevant result).

Faithfulness

The share of claims in the answer that the retrieved context supports.

LLM-as-a-judge

Using an LLM to grade answers against a rubric. Must be checked against human labels.

Regression

A question that got worse after a change.

RAGAS / DeepEval

Open-source libraries that compute RAG metrics.

Remember — measure the two halves separately

Low recall → fix retrieval (parsing, chunking, embeddings, query). High recall but low faithfulness → fix generation (context, prompt, model). This tells you which half to work on.

7Advantages and limitations

Advantages

  • Decisions based on numbers, not impressions
  • Catches regressions before users do
  • Shows which part of the system to fix
  • Makes model and prompt upgrades safe

Limitations

  • Building a good dataset takes expert time
  • Small datasets give noisy results
  • LLM judges have biases and need calibration
  • Offline scores don't capture everything users feel

9How to explain it in an interview

Your 1-minute answer

DefinitionRAG evaluation is the systematic measurement of how well a retrieval-augmented system finds the right evidence and uses it to produce correct answers.

HowI use a versioned golden dataset of questions with expected sources and answers, including unanswerable questions. I measure retrieval with recall@k, MRR and nDCG, and generation with faithfulness, answer relevancy, citation accuracy and abstention accuracy.

ExampleIf recall stays at 0.92 but faithfulness drops from 0.95 to 0.86 after a prompt change, retrieval is fine and the prompt is the problem.

ProcessEvery change is compared with the baseline per metric and per question, regressions are inspected, and a release gate with predefined thresholds decides. LLM judges are calibrated against human labels.

Don't say"We test by asking a few questions and checking if the answers look good."
Say instead"We use a versioned golden dataset and compare retrieval and generation metrics with a baseline."
Don't say"An LLM judge is always reliable."
Say instead"We calibrate the judge against human labels and keep its model and prompt fixed."
