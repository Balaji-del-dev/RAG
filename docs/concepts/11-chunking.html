1What is chunking?

Interview answer — say this first
In simple words

Chunking means cutting long documents into small pieces before storing them for search. Each piece (a chunk) should hold one idea, be small enough to search precisely, and be big enough to make sense on its own.

2Why do we need it?

  • Embedding models have limits. Many can read only 512 or 8,192 tokens. Longer text is cut off.
  • One vector per chapter is too blurry. A whole chapter covers many topics, so its vector matches nothing well.
  • The LLM's context window is limited. Sending 5 small, relevant chunks is better than 5 whole documents.
  • Citations need precision. A chunk points to a specific section and page.

Too small (one sentence)

  • "It must be filed within 10 days." — what must?
  • Context is lost
  • Many vectors to store

Too big (a whole chapter)

  • The vector mixes many topics
  • Search becomes imprecise
  • Wastes the context window
Analogy: the index of a textbook

A good index points you to the right page, not the whole book. If it pointed to a single line, you'd lose the context. If it pointed to a whole chapter, you'd read 30 pages for one fact. Chunking is choosing the right "page size" for search.

3How does it work?

1

Follow the document's structure

Start from the parsed headings, sections, clauses, slides and tables (lesson 09). Natural boundaries make the best cut points.

2

Split big sections to a target size

If a section is too long, split it on the biggest separator that fits: paragraphs, then sentences, then words. A common target is 300–800 tokens, measured with the embedding model's tokenizer.

3

Add a small overlap

Neighbouring chunks share 10–20% of their text, so a sentence on a boundary is not lost.

Example: chunk 1 = tokens 1–500, chunk 2 = tokens 401–900 (100-token overlap)
4

Add a header with the context

Prepend the document title and section path, so the chunk makes sense alone.

Example: "Pricing Guide › Enterprise plan › Support add-on: The fee is ₹500 per month."
5

Save the chunk with its details

Store the text, token count, page numbers, section path and links to the parent and neighbouring chunks.

How to choose the chunk size

ContentGood starting point
FAQ, short facts150–300 tokens, or one chunk per question-and-answer pair
Policies, manualsby section, 300–800 tokens; parent-child for long sections
Contractsone clause per chunk, with the clause number in the header
Tablesa whole small table, or groups of rows with the header repeated
Codeone function or class per chunk
Remember

There is no universal best size. Try 2–3 settings on your evaluation questions and compare recall@k (lesson 20).

5Important terms

Chunk

A piece of a document that is embedded, searched and cited.

Chunk size

How long each piece is, measured in tokens of the embedding model.

Overlap

Text shared by neighbouring chunks, so a sentence on the boundary isn't lost.

Contextual chunk header

The title and section path added to the start of a chunk.

Parent-child chunking

Search with small chunks; give the LLM the bigger parent section.

Contextual retrieval

An LLM writes one sentence explaining where a chunk fits in its document, added before indexing.

Semantic chunking

Split where the meaning changes, found by comparing neighbouring sentences.

Late chunking

Embed the whole document first, then make one vector per chunk, so each chunk keeps document context.

7Advantages and limitations

Good chunking gives you

  • Precise search matches
  • Better use of the context window
  • Exact citations (section and page)
  • Chunks that fit the embedding model's limit

Common mistakes

  • Measuring size in characters instead of tokens
  • Splitting inside a table row or a clause
  • Too much overlap → near-duplicate results
  • Chunks without a title lose their meaning

Real example: contextual chunk headers

Chunk text: "The fee is ₹500 per month." Alone, it matches any question about any fee. With a header — "Pricing Guide › Enterprise plan › Support add-on: The fee is ₹500 per month." — it now matches "How much is Enterprise support?". Anthropic reported that adding generated context to chunks (contextual retrieval) cut failed retrievals by about half, and by about two thirds together with reranking.

9How to explain it in an interview

Your 1-minute answer

DefinitionChunking is the process of splitting documents into smaller, self-contained pieces before they are embedded and indexed.

WhyEmbedding models have token limits, and small focused chunks give more precise matches and use the context window better than whole documents.

HowI start with structure-aware chunking that follows headings, clauses and tables, split long sections recursively to about 300–800 tokens with 10–20% overlap, add the title and section path as a header, and often use parent-child chunking: search small chunks, send the parent section to the LLM.

ValidationThere is no universal best size, so I compare two or three settings on an evaluation set using recall@k before choosing.

Don't say"512 tokens is always the best chunk size."
Say instead"It depends on the documents and questions. I start from the structure and test sizes on an evaluation set."
Don't say"More overlap is always safer."
Say instead"10–20% is typical. Too much overlap creates near-duplicates that crowd the top results."
Don't say"We split by characters."
Say instead"We measure in tokens of the embedding model and never split inside a table row or a clause."
