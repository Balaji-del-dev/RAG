1What is hybrid search?

Interview answer — say this first
In simple words

Hybrid search runs two searches for the same question — one by meaning (vectors) and one by exact words (BM25) — and merges the two result lists into one. A chunk that appears near the top of both lists goes to the top.

2Why do we need it?

Vector search and keyword search fail on different questions (lessons 03 and 14). Real questions often mix both: "What is the penalty in clause 7.3 for late delivery?" — "penalty for late delivery" needs meaning, "clause 7.3" needs exact words. Hybrid search raises recall: the chance that the right chunk is among the candidates.

Only one search

  • Vector only: misses "E-4012", "clause 7.3"
  • Keyword only: misses "car" when the text says "vehicle"
  • The right chunk may never be found

Hybrid search

  • Finds both meaning matches and exact matches
  • Higher recall than either search alone
  • The reranker gets better candidates
Analogy: two expert judges

One judge understands meaning; the other checks exact words. Each produces a ranking. We cannot compare their raw marks — one gives marks out of 1, the other out of 50 — but we can compare positions. A candidate ranked high by both judges is very likely the best. That is Reciprocal Rank Fusion.

3How does it work?

1

Run both searches in parallel

Vector search (e.g. Qdrant) and BM25 search (e.g. OpenSearch) each return their top 20–100 chunks. Both use the same filters and the same index version.

2

Ignore the raw scores, use the positions

A cosine score of 0.82 and a BM25 score of 14.7 are on different scales, so they cannot be added. RRF uses only each chunk's rank (1st, 2nd, 3rd…).

3

Give each chunk an RRF score

For every list a chunk appears in, add 1 ÷ (k + rank), where k is usually 60. Chunks found by both searches collect two scores.

Example: rank 1 in vector + rank 3 in BM25 → 1/61 + 1/63 = 0.0323
4

Sort, remove duplicates and pass on

Sort by the RRF score and send the top 30–50 to the reranker (lesson 17).

The alternative: weighted score fusion

score(d) = α · normalize(vector(d)) + (1 − α) · normalize(bm25(d))      normalize = min-max or z-score per query

This can beat RRF when it is tuned well, but it is sensitive to outliers and α must be tuned on an evaluation set. RRF is the safe default.

5Important terms

Hybrid search

Combining vector (semantic) and keyword (lexical) search for the same question.

RRF (Reciprocal Rank Fusion)

Merges result lists by adding 1 ÷ (k + rank) for every list a document appears in.

Rank constant k

Controls how fast credit drops with rank. 60 is the common value.

Score normalization

Rescaling scores to the same range (e.g. 0–1) before combining them.

Recall

The share of relevant chunks that appear among the candidates.

Candidate pool

The merged set of results passed to the reranker.

7Advantages and limitations

Advantages

  • Higher recall than vector or keyword search alone
  • RRF needs no score calibration
  • Handles both meaning and exact terms
  • Simple to implement

Limitations

  • Two searches: more infrastructure
  • Both indexes must stay in sync
  • RRF ignores how confident each search was
  • Still needs a reranker for precision

9How to explain it in an interview

Your 1-minute answer

DefinitionHybrid search runs semantic vector search and lexical search such as BM25 on the same query and combines their results.

How it worksThe two methods give scores on different scales, so I merge them with Reciprocal Rank Fusion: each document gets the sum of 1 divided by k plus its rank in each list, with k usually 60. Documents ranked highly by both rise to the top.

ExampleFor "penalty in clause 7.3 for late delivery", BM25 finds "clause 7.3" exactly and vector search finds the meaning, so the right chunk is found by both and ranks first.

In practiceEach retriever returns 20–100 candidates with the same filters and index version, and the fused top 30–50 go to a reranker.

Don't say"Add the cosine score and the BM25 score together."
Say instead"The scales differ, so we fuse by rank with RRF, or normalize the scores first."
Don't say"Take the top 5 from each search."
Say instead"Take 20–100 candidates from each, fuse, then rerank. Fusion needs enough candidates."
