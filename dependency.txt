RAG PLATFORM — DEPENDENCIES THAT pip DOES NOT INSTALL
======================================================
Setup: CPU only. Everything runs end to end on ONE local machine — no GPU, no GPU server,
no Docker. All services listen on 127.0.0.1 (localhost) only.
Python packages for the backend are in requirements.txt (it installs the CPU-only PyTorch build).
This file lists everything else. Versions checked on 18 October 2026.


1. THIS MACHINE
---------------
CPU     Intel Core i3-1125G4, 4 cores / 8 threads (AVX2 and AVX-512 supported)
RAM     7.5 GB
GPU     not used
Disk    173 GB free
OS      Ubuntu 24.04.5 LTS

RAM is the main limit. Approximate memory use with the small models in section 6:
  PostgreSQL                         ~0.2 GB
  Redis                              ~0.05 GB
  MinIO                              ~0.15 GB
  Qdrant                             ~0.2 GB
  OpenSearch (heap set to 512 MB)    ~1.0 GB
  Django API + embedder + reranker   ~0.9 GB
  Celery worker (Docling, OCR)       ~1.5–2 GB  (only while documents are processed)
  Ollama with qwen2.5:3b             ~2.5 GB
  Ubuntu desktop + browser           ~2 GB
  ------------------------------------------
  Total while ingesting and chatting ~8.5–9 GB  -> more than 7.5 GB
How to make it fit:
  - Process documents and chat at different times (stop the Celery worker while chatting).
  - Run only one Celery worker with --concurrency=1.
  - Use qwen2.5:1.5b (~1.2 GB) instead of qwen2.5:3b when memory is short.
  - Set OLLAMA_MAX_LOADED_MODELS=1 and OLLAMA_NUM_PARALLEL=1.
  - Close other browser tabs and applications.
  - Recommended upgrade: 16 GB RAM.
Expected speed on this CPU (rough estimate): about 20–60 seconds per answer.
Send only 3–4 short chunks to the LLM to keep it nearer the low end.

6. LOCAL MODELS (small, CPU-friendly; download once, no downloads at runtime)
----------------------------------------------------------------------------
Generation LLM (through Ollama)
  qwen2.5:3b              installed (1.9 GB)        default — best quality that fits this machine
  qwen2.5:1.5b            ollama pull qwen2.5:1.5b  lighter option when RAM is short
  llama3 (8B), gemma3     installed, but too big to run next to the other services on 7.5 GB

Embedding model (sentence-transformers, inside the backend)
  intfloat/multilingual-e5-small   118M parameters, 384 dimensions, 512-token limit, MIT license
                                   English + Tamil + Hindi; needs "query: " / "passage: " prefixes
                                   keep chunks at or below ~400 tokens
  BAAI/bge-small-en-v1.5           33M parameters, MIT — faster, English only
  (all-minilm in Ollama is English only with a 256-token limit, so it is not recommended)

Reranker (cross-encoder, inside the backend)
  cross-encoder/ms-marco-MiniLM-L6-v2   23M parameters, Apache-2.0 — fast on CPU, English
  BAAI/bge-reranker-v2-m3               568M parameters, Apache-2.0 — multilingual but slow on CPU;
                                        rerank only the top 10–20 candidates

Other models
  Docling layout and table models  download with: docling-tools models download (runs on CPU)
  EasyOCR weights                  use gpu=False; only as a fallback when Tesseract is not enough
  spaCy en_core_web_sm             for Presidio PII detection (smaller than en_core_web_lg)
  Evaluation judge                 the same qwen2.5:3b through Ollama; small judges are less
                                   reliable, so check their scores against human labels

CPU settings
  OMP_NUM_THREADS=4  and  torch.set_num_threads(4)   use the 4 physical cores
  HF_HUB_OFFLINE=1  and  TRANSFORMERS_OFFLINE=1      after the downloads, never download at runtime
