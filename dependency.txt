RAG PLATFORM — DEPENDENCIES THAT pip DOES NOT INSTALL
======================================================
Python packages for the backend are in requirements.txt.
This file lists everything else: runtimes, services, model servers,
system packages, local model files and frontend packages.
Versions are the latest stable releases checked on 18 October 2026.


1. RUNTIMES
-----------
Python            3.12          backend (Django + DRF, Celery workers)
Node.js           24.22.0 LTS   frontend build tooling (npm included)


2. SERVICES (each runs as its own server on the private network)
----------------------------------------------------------------
PostgreSQL        18.6          system of record: documents, chunks, jobs, configuration, answers, evaluation
Redis             8.10.2        Celery broker and result backend, caches
MinIO             RELEASE.2025-10-15T17-29-55Z
                                object storage for original files and extracted artifacts
                                NOTE: the MinIO community repository is archived (last release
                                October 2025). Decide whether to stay on it or move to another
                                S3-compatible store; the backend only needs the S3 API.
Qdrant            1.19.2        vector index (one collection per index generation)
OpenSearch        3.9.0         BM25 keyword index (one index per generation)
Flower            (pip)         Celery monitoring UI; installed from requirements.txt
Langfuse server   4.63.0        tracing and observability (optional)
                                needs PostgreSQL, Redis or Valkey, ClickHouse 26.7 and S3-compatible storage
                                NOTE: Langfuse is officially deployed with Docker Compose or Kubernetes,
                                which conflicts with the "no Docker" rule — decide before setup.


3. MODEL SERVERS (behind the LiteLLM gateway)
---------------------------------------------
Ollama            0.40.6        simple local LLM serving (development, small teams)
vLLM              0.32.0        high-throughput GPU serving for production
                                install in its own virtual environment: pip install vllm==0.32.0
                                (vLLM 0.32.0 requires torch==2.13.0, the backend uses 2.14.1,
                                so they cannot share one environment)

5. GPU (for the LLM, embeddings, reranker and EasyOCR)
------------------------------------------------------
NVIDIA GPU driver and CUDA runtime that match the PyTorch build.
Install the CUDA build of torch from the PyTorch package index for your CUDA version;
the plain "pip install torch" build is enough for CPU-only development.


6. LOCAL MODEL FILES (download once during setup; no downloads at runtime)
-------------------------------------------------------------------------
Record the exact revision and SHA-256 of every file. Use safetensors or GGUF formats only.
Generation LLM      e.g. an 8B instruct model (GGUF for Ollama, safetensors / AWQ for vLLM)
Embedding model     e.g. BGE-M3 or Qwen3-Embedding-0.6B
Reranker            e.g. bge-reranker-v2-m3 or Qwen3-Reranker-0.6B
Docling models      layout and table models: docling-tools models download
EasyOCR weights     detection and recognition models for the configured languages
Presidio NLP model  a spaCy model such as en_core_web_lg (PII detection)
Evaluation judge    a local LLM served through Ollama or vLLM, used by DeepEval
Set HF_HUB_OFFLINE=1 and TRANSFORMERS_OFFLINE=1 after the downloads.
